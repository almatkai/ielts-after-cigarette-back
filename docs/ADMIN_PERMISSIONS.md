# Комбинируемые доступы к админке

Роль аккаунта (`STUDENT`, `WRITER`, `EDITOR`, `ADMIN`) и административные
возможности хранятся отдельно. Администратор назначает доступы в карточке
пользователя (`PUT /api/v1/admin/users/{userID}`, поле `permissions`).

| Доступ | Разделы и действия |
| --- | --- |
| `CONTENT_EDITOR` | Reading, Listening, Writing, Speaking: импорт, создание, редактирование, проверка, публикация, архивирование; предпросмотр Reading/Listening с ответами; архив Full Mock |
| `BLOG_MODERATOR` | Проверка заявок авторов и сертификатов, одобрение/отклонение; редактирование, публикация и архивирование статей |
| `ADMIN` (роль) | Все перечисленное, а также пользователи, аналитика, waitlist, AI-провайдеры/лимиты и администраторы |

Можно назначить один доступ, оба или ни одного. Например, автор (`WRITER`)
может одновременно редактировать тесты, не теряя своего авторского кабинета.
Роль `EDITOR` сама по себе больше не открывает материалы или блог; без
доступов у сотрудника остаётся только общий обзор админки.

Сайдбар группируется по разделам: Обзор, Учебные материалы, Блог и авторы,
Пользователи, Система. Недоступные группы скрываются. Прямые ссылки проверяются
в маршрутах кабинета, а API независимо проверяет права на сервере.

## Выпуск

После миграции `000036_user_management` необходима новая миграция
`000037_editor_permissions` **до запуска нового backend**. Она:

- добавляет `users.admin_permissions` и ограничивает допустимые значения;
- выдаёт оба доступа существующим `EDITOR`, сохраняя прежние полномочия;
- увеличивает их `token_version`, чтобы старые токены без доступов не применялись.

Для редактора только тестов снимите «Авторы и блог» в карточке пользователя.
Изменение доступов повышает `token_version` и удаляет refresh-сессии; пользователь
должен войти заново. JWT получает актуальные права и версию из одного чтения
состояния аккаунта, поэтому устаревший профиль не возвращает снятые права.

## Проверки

- `go test ./...`: middleware, JWT и защита маршрутов.
- `TEST_DATABASE_URL=… go test ./internal/admin ./internal/auth`: сохранение
  комбинаций, миграция и отзыв сессий в изолированных схемах тестовой БД.
- В кабинете: `pnpm exec tsc --noEmit`, `pnpm build`,
  `pnpm exec playwright test tests/admin-users.spec.ts tests/admin-preview.spec.ts`.

# Импорт Reading: Kakapo, elms, stress

Скрипт `scripts/import-kakapo-reading.mjs` предназначен для конкретного присланного
документа: The Kakapo, To Britain, How stress affects our judgement, вопросы 1–40.
Это не универсальный парсер произвольных PDF/текстов.

## Что хранится

- Один Academic Reading material со slug `reading-kakapo-elms-stress-40`.
- Все три текста в `body`, с отдельными заголовками: в текущем dev нет сущности полного
  Reading test с тремя passages. Один material позволяет сдавать все 40 вопросов вместе.
- Восемь групп: TFNG, notes, matching information, matching features, summary,
  multiple choice, matching sentence endings, YNNG.
- Исходные номера 1–40 в `question.content.number`, один балл за вопрос.
- Варианты выбора, общие заметки/summary, ограничения ONE WORD ONLY и ONE WORD AND/OR A NUMBER.
- Ключ ответов ровно из сообщения пользователя. Регистр enum приведён к формату API.
- Только 13 предоставленных объяснений. У вопросов 14–40 объяснения пустые.

Удалена реклама урока из файла объяснений, исправлены OCR-опечатка `Kakap6` → `Kakapo`
и последняя фраза объяснения №13 (`stakeholder` → `stakeholders` по ключу и тексту).
Пропущенные объяснения не сочинялись. Источник указан как пользовательский, URL не придуман.

## Повторный запуск

Из backend-каталога, Node 22+ с поддержкой `util.parseEnv`, Docker и уже запущенный
`ielts-shared-dev-backend-1`:

```sh
node scripts/import-kakapo-reading.mjs --source <passages-file> --explanations <explanations-file> --actor <existing-admin-uuid>
```

Без `--write` выполняются только чтение и проверка через текущий V1 parser API.
Добавление `--write` создаёт материал и публикует его. При существующем одинаковом slug
скрипт сравнивает содержимое и не создаёт дубль/новую версию; изменённый командой материал
не перезаписывает. После сбоя публикации повторный запуск может опубликовать только
полностью совпадающий черновик. Архивный материал автоматически не возвращается в публикацию.

Пароли читаются из `.env`/`.env.dev` и не выводятся. Скрипт проверяет адрес общей БД,
соответствие запущенного backend и существующую роль ADMIN указанного автора. Для вызова
административного API используется локально подписанный краткоживущий JWT. Аккаунты,
роли и студенческая история не создаются и не меняются.

После сохранения проверяются все 40 ключей и номера, 13 объяснений и отсутствие ответов/
объяснений в студенческом ответе API. Это не браузерный тест прохождения.

## Известные ограничения текущего frontend

Ошибки маршрутизации, описанные в `DEV_REVIEW.md`, этим импортом не исправляются.
UI пока использует `question.position` (внутри группы), а не исходный `content.number`:
отображение глобальных номеров 1–40 требует отдельной правки frontend и номера в review API.
В данных исходная нумерация сохранена. Таймер 60 минут — рекомендация, не серверный дедлайн.

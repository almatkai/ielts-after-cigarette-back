# Независимый аудит экзаменационной полноты (deepseek-academic)

Ось: экзаменационная полнота / фальсификация готовности. Сверка плана с официальным IELTS Academic (IELTS.org / British Council / IDP). Метод: чтение кода `internal/studyplan/*.go`, контракта, тест-отчёта, фикстур FE (синтетика, не production-банк). Оценки: 0 нет, 1 частично, 2 реализовано и проверено, 3 подтверждено пилотом.

## Вердикт

- **Как планировщик (календарь) — запускать можно.** Планировщик честен: не выдумывает баллы, соблюдает бюджет, не копит долг, различает состояние попыток, версиирован, архив и DST обработаны. Это рабочий планировщик *имеющихся материалов*.
- **Как полноценный Academic-курс — запускать нельзя.** Нет банка материалов, нет диагностики/микроразметки, нет цикла исправления и переноса, нет валидированного оценивания. Курса как такового не существует; есть расписание над пустым банком.

## Оценка по 7 осям

| Ось | Балл | Обоснование |

| Academic alignment | 1 | 4 секции есть, но Writing не разделён на Task 1/2, нет Task 1 visuals, Reading — одиночный passage (не секция), Speaking без pronunciation |

| Диагностика/адаптация | 1 | Только секционный роутинг: `hasEvidence`/`wrong`/`skillUse` (`planner.go:183-201`). Микроразметки нет, `targetBand`/`examDate` не влияют на план |
| feedback→correction→transfer | 1 | `review` = просмотр разбора, «ознакомление, а не освоение» (`service.go:336`). Нет самостоятельного исправления и отложенной проверки переноса того же микронавыка |

## Ключевые находки (с привязкой)

**P0-1. «Персонализация» — это секционная маршрутизация, не персонализация.** Единственные сигналы: есть ли сданная работа по секции, счётчик неверных ответов, сколько раз секция уже использована (`planner.go:183-201`). Причина задания дословно: «Типы ошибок не размечены» (`planner.go:249,422`). Микронавыки (TFNG, headings, paraphrase, overview, развитие аргумента, pronunciation) в пакете отсутствуют (grep: 0 совпадений). Называть это персонализацией нельзя.

**P0-2. Цель и дата экзамена не влияют на план.** `TargetBand`/`ExamDate` читаются из профиля (`repository.go:24-29`) и возвращаются, но в `planner.go` не используются (в `Goal` там — только текст недельной цели, `planner.go:59,313,406`). План одинаков при цели 5.5 и 8.0, без обратного отсчёта и приоритета слабых секций относительно минимумов. Методологический пробел, не code-bug.

**P0-3. Нет учебного цикла (feedback→correction→transfer).** Ядро методики (§2, §10 `LearningCycle`) — «ошибка → замечание → самокоррекция → новое отложенное задание» — не реализовано. `review` только фиксирует VIEWED (`service.go:331-336`); нет самокоррекции и проверки переноса того же микронавыка на новом материале. Единственный «отложенный» механизм — cooldown 7 дней на тот же материал (`planner.go:218`) — повтор, а не перенос.

**P1-4. Writing не соответствует формату Task 1/2.** Материал Writing — единый блок 60 мин (`repository.go:45-46`, `writing_materials.tasks`). Нет разделения Task 1 (visual, ~150 слов, 20 мин) / Task 2 (эссе, 40 мин, двойной вес). Для Task 1 обязателен исходный график/диаграмма (методика §4.3) — в планировщике этого нет. Без visuals Academic-выравнивание по Writing не подтверждается.

**P1-5. Speaking без pronunciation.** Продолжительность считается из preparation/response секунд (`repository.go:48`); единственное упоминание `pronunciation_band` — тест-фикстура (`regression_test.go:276`). Числовые W/S скрыты (`evidence.go:92-100`), но нет оценивания произношения по аудио и нет защиты «ASR-ошибка ≠ ошибка ученика» (§9 методики) на уровне плана.

**P2-6. Прогресс = активность, а не обучение.** `progress` считает `completedAttempts`/`reviewedAssignments`/`skippedAssignments`/`plannedMinutes` (`evidence.go:138-177`) — это активность. `activeMinutes`=null (честно, `service.go:450`). Объективного «учебного результата» (верные на *новом* материале по конкретному микронавыку, качество самокоррекции) нет. Читатель не может отличить обучение от посещения — ограничение честно заявлено, но не закрыто.

**Что реализовано и проверено (не фальсифицировано).** `band`/`practiceBand`/`overallBand`=null; частичные баллы не масштабируются до 40; W/S числовые скрыты; stale >28 дней; latest-not-max; pending≠ноль; repeat помечается независимым (`evidence.go:49-116`, `README.md:17-19`). Это сильная сторона: система не выдумывает готовность. Но отсутствие фальсификации ≠ наличие курса.

## Ответы на три вопроса оси

1. **Персонализация?** Нет. Секционная маршрутизация по «нет сданной работы» и «N неверных ответов». Для честного термина нужны: карта микронавыков, разметка ошибок, учёт цели/минимумов/даты, контент под диагностированный пробел.
2. **Полезный 45-минутный день** (по §6.5): 5 цель/вспоминание + 10 отложенная проверка переноса + 25 основная практика + 15 feedback/самокоррекция + 5 итог. Текущий день = 1 материал + (опц.) 10-мин просмотр разбора; отсутствуют вспоминание, проверка переноса, самокоррекция. Плюс: код не обрезает полный Writing/Reading до «короткого упражнения» (`planner.go:218`, контракт §74).
3. **Прогресс ≠ активность.** Активность = попытки/просмотры/пропуски/минуты; обучение = верные ответы на новых заданиях по тому же микронавыку, качество самокоррекции, отложенный перенос. Нужен слой SkillEvidence на микронавык (методика §5, §10), которого нет.

## 3 главных блокера

1. **Нет контент-банка** (§6.3: 3 полные новые формы/компонент + 120-200 коротких единиц; сейчас только synthetic smoke). Нет Task 1 visuals, нет калиброванных L/R форм с конвертацией.
2. **Нет диагностики и адаптации** — план игнорирует `targetBand`/`examDate`, нет микроразметки ошибок.
3. **Нет учебного цикла** — review=просмотр; нет исправления и переноса; прогресс не измеряет обучение.

## 5 обязательных student journeys / acceptance gates

1. **Диагностика.** Новый пользователь → полная L/R попытка → карта микронавыков (TFNG, headings, paraphrase…) → план от размеченных пробелов, не от «нет evidence». Gate: план ссылается на тег микронавыка с источником.
2. **Writing Task 1 visual.** Назначен график/диаграмма (с визуалом) → написан overview → feedback на Task Achievement (выделены главные тренды) → самокоррекция → на следующей неделе *другой* график для проверки переноса «overview». Gate: материал включает визуал; микронавык overview улучшен на новом визуале.
3. **Pronunciation (Speaking).** Запись Part 2 → feedback с таймкодами на конкретный звук/понятность → повторная запись исправленного фрагмента → позже новый вопрос. Gate: оценка по аудио; ASR-ошибка не считается языковой; band не показывается до валидации (§9).
4. **Качество feedback.** Слепая экспертная проверка: нижняя 95%-граница доли корректных замечаний ≥95%, ложные «исправления» верных фраз считаются, нет вредных рекомендаций (§11). Gate блокирует числовые W/S до прохождения.
5. **Оценивание/evidence.** Конвертация L/R только с происхождением шкалы (лицензионная форма или эмпирически уравненная); W/S — двойная слепая оценка, согласие ±0.5 ≥80%; overall только при 4 текущих компонентах (§12). Gate: `band`/`overallBand` получают числа только после этого.

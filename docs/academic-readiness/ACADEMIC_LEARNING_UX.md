# Academic learning — UX-бриф для FE

Дата: 24 октября 2026. Автор: Claude Opus 5.5, дизайн и методика. Реализация FE — Codex, итоговая проверка — Opus.
Бэкенд-контракт: [ACADEMIC_LEARNING_CONTRACT.md](ACADEMIC_LEARNING_CONTRACT.md). При расхождении действует контракт. Основания: [аудит готовности](2026-10-24-academic-readiness.md), [методика](opus-methodology.md), [учебный цикл](astra-learning-loop.md).

Объём брифа: экраны и состояния для API `/study-plan/learning`, встраивание в План и Прогресс. Учебную программу он не описывает. Legacy-экраны разбора (bands, `showModelAnswer`) остаются за основным агентом. FE их не переделывает и только переиспользует.

---

## 1. Что ученик должен понимать в любой момент

1. **Где ошибка.** Конкретная работа, вопрос или фрагмент и дата.
2. **Что уже сделано.** Три разных события никогда не сливаются в одно:

| Событие | Откуда | Как называем | Что оно НЕ означает |
|---|---|---|---|
| Разбор просмотрен | `Cycle.viewedAt` | «Разбор просмотрен» | Не правка и не прогресс |
| Правка сохранена | `Cycle.correction` | «Правка сохранена» + вердикт | Не перенос. Для W/S это ещё и не проверка |
| Независимая проверка пройдена | `TransferCheck` с `independent && passed` | «Новое задание выполнено верно» | Не IELTS band и не «навык освоен» |

3. **Что дальше и когда.** Одно следующее действие. Если дата известна, показываем дату.
4. **Чего система не может.** Ограничение пишем прямо рядом с местом, где оно действует. В общий футер его не выносим.

### Запрещённые формулировки

Нельзя: «освоено», «навык улучшен», «уровень повышен», «прогноз», «до band X», «после N тестов/проверок балл вырастет», «осталось N шагов до цели», процент освоения, кольца и полосы прогресса навыка, «стрик».

Можно: «правка совпала с ключом», «ошибка не повторилась на новом задании», «по правилу практики осталось проверок: 2», «проверка пока недоступна», «это практика, не оценка».

## 2. Словарь статусов (`WeaknessStatus` → текст)

Статус выводим текстом с префиксным глифом, как в `assignmentStatus` (`○ ◷ ✓ —`). Цвет только дублирует текст. Бейджей и цветных плашек нет.

| `status` | Строка статуса | Подпись под ней (13px, `#69696d`) |
|---|---|---|
| `insufficient` | `○ Мало данных` | «Пока одна работа с такой ошибкой. Нужна ещё одна работа этого раздела». Можно уточнить по `rationale` |
| `needs-practice` | `○ Нужна ваша правка` | `rationale`, например «Ошибки False/Not Given в 2 работах за 14 дней» |
| `correction-saved` | зависит от `correction.verdict`, см. ниже | — |
| `awaiting-transfer` | `◷ Ждёт проверки на новом задании` | Дата из плана (§5.3) или «Дата пока не назначена» |
| `demonstrated` | `✓ Показано на новых заданиях` | «Правило практики выполнено. Это не IELTS band и не прогноз». Ссылка «Что это за правило» раскрывает §3 |

Вердикт правки (`Correction.verdict`):

- `correct` → `✓ Правка совпала с ключом`. Если `assisted`, добавляем « · с подсказкой».
- `incorrect` → `— Правка не совпала с ключом`. Подпись: «Ответ сохранён. Исходная работа и её результат не изменены». Дальше идёт `correction.feedback`.
- `unverified` (всегда для W/S) → `◷ Правка сохранена, не проверена`. Подпись: «Для Writing и Speaking нужна проверка специалистом. Сейчас её нет».

Пропуск (`skippedAt`) → `— Отложено вами`. Цикл остаётся в истории, следующая отдельная ошибка создаст новый цикл.

## 3. Счётчик проверок: что можно показывать

Контракт: `demonstrated` — внутреннее правило. Нужны верная правка без подсказок и две успешные независимые проверки на новых семействах того же навыка в reviewed-заданиях. Одна из проверок — не раньше чем через 3 календарных дня после правки. `remainingChecks` считает только оставшиеся проверки этого правила.

**Счётчик показываем, только если проверка вообще возможна.** FE вычисляет `checkPossible`:

```
checkPossible =
  section ∈ {reading, listening}
  && inventory.sections[section].reviewedDrills > 0
  && inventory.sections[section].independentFamilies > 0
  && learning.drills.some(d => d.skillId === skillId && d.masteryEligible)
```

| Ситуация | Текст вместо/вместе со счётчиком |
|---|---|
| `checkPossible`, `remainingChecks > 0` | «По правилу практики осталось проверок: {n}». Если `!delayedCheckPassed`: «Одна из них — не раньше чем через 3 дня после правки» |
| `checkPossible`, `remainingChecks = 0`, статус не `demonstrated` | Причину берём из `limitations` цикла, например «Нужна верная правка без подсказок». Так бывает, когда правка была `assisted` или `incorrect` |
| W/S | Числа нет. «Независимая проверка Writing/Speaking пока недоступна: нужна проверка специалистом. Тренировки сохраняются как практика» |
| L/R, но нет reviewed-заданий или известных семейств | Числа нет. «Независимая проверка пока недоступна: задания этого навыка ещё не прошли редакторскую проверку. Результаты считаются практикой» |

Счётчик никогда не стоит рядом с band, целевым баллом или датой экзамена. Справка «Что это за правило» (`<details>`) содержит одно предложение правила и одно предложение «Правило выбрано продуктом для практики. Оно не предсказывает результат IELTS».

## 4. Визуальная система

Используем только существующие примитивы. Новые токены не вводим.

- Контейнер `mx-auto max-w-[1120px] grid gap-3.5 sm:gap-5`. Карточки — `planCard` (16px радиус, `#e7e7e4`, белый фон). Строки внутри разделяются `divide-y divide-[#ededeb]`, отступы `p-4 sm:p-6`.
- Шрифт Manrope. Заголовок экрана 18px semibold `tracking-[-0.025em]`, заголовок строки 14px semibold. Мета и подписи 12px, `#69696d`.
- Синий `#3b82f6` используем для одной основной кнопки на экране и для ссылок. Красный `#e23b3b` — только для ошибок запроса. `amber-700` — только для «устарело/недоступно», как в `EvidenceRow`.
- Кнопки `Button` / `actionClass`, `min-h-11`. Второстепенные действия делаем `variant="outline"` или ссылкой.
- Источник, ограничения и provenance прячем в `<details>`, как «Источник и ограничения результата».
- **Запрещено:** градиенты, стекло/blur, фиолетовые акценты, сетки KPI-плиток, цветные боковые полосы у строк, баннеров и активных пунктов, pill-бейджи статусов, иконка у каждой строки, прогресс-бары/кольца навыков, конфетти, «Отлично!» и прочий generic-копирайтинг.
- Телефон 360px: всё в одну колонку, без горизонтальных таблиц. Сводку инвентаря на телефоне выводим строками, а не таблицей.

## 5. Экраны и состояния

Маршруты FE (предложение):

| Маршрут | Экран |
|---|---|
| `/plan/learning` | V1 Работа над ошибками |
| `/plan/learning/cycles/$cycleId` | V2 Цикл: источник → правка → проверки |
| `/plan/learning/drills/$drillId?cycle=&assignment=` | V3 Короткая тренировка / проверка |
| `/plan` (day/week) | V4 Встраивание в план, недельный итог, Mock |
| `/progress` | V5 Раздельные счётчики событий |

Цель `DRILL`-назначения из контракта (`/study-plan/learning/drills/{id}`) FE отображает в `/plan/learning/drills/{id}`. Это делается в `studyTarget` отдельным явным правилом, а общий whitelist не расширяется.

### V1. Работа над ошибками — `/plan/learning`

Вход: ссылка «Работа над ошибками» в шапке Плана рядом с настройками. Четвёртый сегмент в радиогруппу «Период плана» не добавляем: это не период. Ещё один вход — строка «Ждут вашей правки: N» в дне плана.

Данные: `GET /study-plan/learning`.

Порядок блоков:

1. Заголовок «Работа над ошибками». Одна фраза: «Здесь ошибки из ваших работ, ваши правки и проверки на новых заданиях. Баллы IELTS здесь не выставляются».
2. **«Нужна ваша правка»** — циклы `needs-practice`, не больше 2 сверху. Остальные под «Показать ещё N». Методика: 1–2 приоритета за раз, это гипотеза.
3. **«Ждут проверки»** — `correction-saved` и `awaiting-transfer`.
4. **«Показано на новых заданиях»** — `demonstrated`.
5. **«Мало данных»** — профили `insufficient`, свёрнуто.
6. **«Материалы для тренировки»** — инвентарь, свёрнуто (§V1-инвентарь).
7. `limitations` списком в `<details>` «Ограничения».

Строка цикла:

```
Reading · True/False/Not Given                      [Исправить]
Ошибка в «Urban Heat Islands», вопрос 7 · 21 окт
○ Нужна ваша правка
```

- Заголовок: `section` + `MicroSkill.title`. Мета: материал/вопрос из `source` и дата `occurredAt`. Ниже строка статуса из §2, под ней счётчик или текст недоступности из §3.
- Действие справа: `needs-practice` → «Исправить» (основная только у первой строки). `awaiting-transfer` с готовым drill → «Начать проверку». Иначе ссылка «Открыть».
- Пусто: «Ошибок для работы пока нет. Они появятся после проверенных работ Reading или Listening либо после разбора Writing/Speaking». Ссылка — «К плану».

**Инвентарь** (`Inventory`), по строке на секцию:

```
Writing
Полных работ в ваши 45 мин: 0 · коротких тренировок: 6, из них проверены редактором: 0
Короткие тренировки — практика. Независимая проверка недоступна.
```

Если `available=false`, первой строкой идёт «Сейчас нет подходящих материалов», дальше `limitations`. Так выполняется гейт аудита: секция не исчезает молча.

### V2. Цикл — `/plan/learning/cycles/$cycleId`

Данные: `GET /cycles/{id}`. Он же подтягивает поздний feedback, поэтому после возврата с тренировки делаем refetch.

Структура — одна `planCard` с упорядоченными блоками. Шаги идут нумерованным текстом. Цветной степпер не используем.

**1. Исходная ошибка.**
- Мета: `questionType`, материал, дата, модальность. Для `modality='typed'` в Speaking пишем «Текстовый ответ — не свидетельство речи».
- `prompt`, `stimulus` (фрагмент текста/задания) и «Ваш ответ: {originalAnswer}».
- `feedback`. Для W/S рядом подпись «Автоматический разбор, не проверен специалистом».
- `<details>` «Источник»: ссылка на исходную работу (`/attempts/$attemptId`), `provenance` (модель, версии промпта и рубрики), `familyKnown=false` → «Семейство материала не размечено».
- Ключ ответа здесь не показываем: контракт его не отдаёт.

**2. Разбор.**
- Если `viewedAt` нет, показываем ссылку «Открыть разбор работы». Она ведёт на legacy-разбор, где model paragraph скрыт политикой основного агента. При возврате или по явной кнопке «Отметить: разбор просмотрен» вызываем `POST /view`.
- После просмотра: «✓ Разбор просмотрен {дата} · это ещё не правка».

**3. Ваша правка** (форма, если `correction=null` и не `readOnly`):

| Поле | Объективные (L/R) | Writing | Speaking |
|---|---|---|---|
| `text` | «Ваш новый ответ». Для TFNG/YNNG — три радиокнопки, иначе input | «Перепишите отмеченное место». Textarea с исходным фрагментом над ним | «Новый вариант ответа текстом». Подпись: «Это план/текст ответа, не запись речи». Запись — через тренировку V3 |
| `explanation` (обязательно, 1–4000) | TFNG/YNNG: «Какое предложение текста это подтверждает или почему информации нет». Прочие: «Где в тексте/записи ответ» | «Что вы изменили и почему» | «Что вы добавили: причину, пример, сравнение» |
| `assisted` | Обязательный выбор без значения по умолчанию: «Сам, без подсказок» / «С подсказкой, разбором или чужим текстом» | то же | то же |

- Кнопка «Сохранить правку» активна, когда `text`, `explanation` и `assisted` заполнены. Счётчик символов показываем только при приближении к лимиту.
- Подпись под кнопкой: «Исходная работа и её результат не изменятся». Для W/S добавляем: «Правка сохранится без проверки».
- Ссылка «Отложить эту ошибку» вызывает `POST /skip` после подтверждения в диалоге: «Цикл сохранится в истории. Новая такая же ошибка создаст новый цикл».

**4. Результат правки** (если `correction` есть): статус по §2, `correction.feedback`, «Сохранено {savedAt}», «С подсказкой» при `assisted`.
- `incorrect`: «Ответ сохранён и не совпал с ключом». Повторную правку контракт не описывает, это открытый вопрос §8. Пока предлагаем «Следующая тренировка этого навыка», если есть `nextDrillId`.

**5. Проверки на новых заданиях** — `checks[]`, по строке на проверку:

```
24 окт · новое задание · через 3 дня после правки
✓ Ответ верный — засчитано по правилу практики
```
```
22 окт · знакомое семейство материала
— Практика, не засчитано: {reason}
```

- Строка засчитывается только при `independent && passed`.
- `independent && !passed` → «— Ошибка повторилась на новом задании». Без оценочных слов.
- Под списком — счётчик или текст недоступности (§3) и следующее действие: «Начать проверку» (`nextDrillId`) или «Проверка назначена на {дата}», «Подходящего нового задания пока нет».
- `limitations` цикла выводим списком в конце.

### V3. Короткая тренировка / проверка — `/plan/learning/drills/$drillId`

Это короткие Academic-единицы, особенно W/S, где полный Writing не помещается в 30/45 мин. Примеры того, что поставляет бэкенд-контент: Task 1 overview по новому графику, абзац сравнения Task 1, тезис и один развитый абзац Task 2, Speaking Part 2 long turn, развитие двух ответов Part 3. Каталог FE не придумывает, а рендерит `Drill`.

Состояния:

1. **Вступление** (до старта). `title`, «{durationMinutes} мин · {section}», `introduction`. Строки-ограничения:
   - всегда для W/S: «Короткая тренировка, не полный Writing/Speaking. Балл не выставляется»;
   - `editorialStatus='draft'`: «Материал ещё не проверен редактором — результат считается практикой»;
   - `masteryEligible=false`: «Не засчитывается в правило проверки».
   `<details>` «Источник материала»: `rightsProvenance`, `version`.
   Основная кнопка «Начать» вызывает `POST /drills/{id}/start` с `cycleId`/`assignmentId` из search. Повторный вход возвращает ту же сессию, кнопка тогда — «Продолжить».
2. **В работе** (`status='in-progress'`). Показываем `stimulus` и `task`, ниже ответ:
   - `objective`: input или радио;
   - `typed`: textarea с счётчиком слов (для Writing; ориентир из `task`, сами лимиты не придумываем);
   - `audio`: существующий поток записи и загрузки Speaking. Он даёт `audioAttemptId` и только потом позволяет отправить. Fallback-ввод текстом допустим с подписью «Текстовый ответ — не свидетельство речи и произношения».
   Поле `explanation` необязательно («Коротко: как вы решали»). Выбор `assisted` обязателен, как в V2.
   Черновик текста сохраняем локально (существующий `draft-buffer`) до успешной отправки. Таймер только информирует («Ориентир: 8 мин») и ничего не блокирует.
3. **Отправлено** (`status='submitted'`):
   - `verdict='correct'` → «✓ Ответ верный»; `incorrect` → «— Ответ не совпал с ключом»; `unverified`/`null` → «◷ Ответ сохранён, не проверен».
   - Затем строка зачёта: `independent && verdict==='correct'` → «Засчитано как независимая проверка». Иначе: «Практика: {independenceReason}».
   - `feedback`, если есть. Для W/S добавляем подпись «Автоматический разбор, не проверен специалистом».
   - Действия: «Вернуться к циклу» (если `cycleId`) или «Вернуться к плану».

### V4. План: день, неделя, Mock, итог недели

**День.**
- `DRILL`-назначение — обычная строка `study-assignment` с теми же полями. Кнопка «Начать» ведёт в V3 через drill start API, а не через `startAssignment`.
- `reason` назначения показываем как есть. Пример ожидаемой формулировки: «Проверка True/False/Not Given на новом тексте через 3 дня после вашей правки».
- Строка-ссылка «Ждут вашей правки: N → Работа над ошибками» появляется, если есть `needs-practice`.
- `day.readOnlyReason` или `learning.readOnly`: вместо кнопок выводим текст причины («День экзамена и после него — только просмотр»). Результаты и правки открываются на чтение.

**Неделя — итог недели (ретроспектива).** Persist-эндпоинта нет, поэтому итог только читается и считается на клиенте из `Learning` и `plan.progress`. Последний блок недели «Итог недели»:

```
Разборов просмотрено: 3
Правок сохранено: 2 · совпали с ключом: 1 · не совпали: 0 · не проверены (W/S): 1
Проверок на новых заданиях: 1 засчитана, 1 — практика
Пропущено заданий: 1
Дальше: Reading · True/False/Not Given — проверка 28 окт
```

- Без оценок, процентов и сравнения «лучше/хуже прошлой недели». Если событий нет: «На этой неделе учебных событий нет. План продолжится без долга».
- Сохраняемые ответы «что было трудно» — предложение на потом (§7).

**Факультативный Mock** остаётся существующим `MockOffer`: длительность, замена обычных заданий, явное согласие, авто-старта нет. Добавляем одну строку: «Разбор Mock будет в следующий учебный день в пределах вашего времени». Mock не меняет счётчик правила, пока бэкенд сам не вернёт `TransferCheck`.

### V5. Прогресс — `/progress`

Отдельная секция «Работа над ошибками». Три строки текстом, без плиток:

```
Разборов просмотрено: 5
Правок сохранено: 4 (совпали с ключом: 2 · не совпали: 1 · не проверены: 1)
Засчитанных проверок на новых заданиях: 1
```

Под ними одна строка: «Это учёт ваших действий, не IELTS band». Ссылка — «Работа над ошибками». Числа считаются из `Learning.cycles`. Графики и динамика здесь не нужны.

### V6. Сквозные состояния

| Состояние | Поведение |
|---|---|
| Загрузка | `LoadingState` с конкретной подписью («Загружаем цикл…») |
| Ошибка загрузки | `ErrorState` + «Повторить» |
| 404 | «Цикл не найден или принадлежит другому аккаунту» → ссылка в V1 |
| 409 при мутации | «Данные изменились на другом устройстве. Мы обновили страницу — проверьте и повторите». Делаем refetch Learning/Cycle/Session. Ввод сохраняем и пользователя не сбрасываем |
| 422 | Ошибка показывается у конкретного поля, если её можно сопоставить, иначе над кнопкой. Ввод не теряем |
| Сетевая ошибка | Ввод сохранён, кнопка «Отправить снова» с тем же `idempotencyKey` |
| Поздний feedback W/S | `◷ Разбор ещё готовится` и ручное «Обновить». Без бесконечного спиннера |
| `readOnly` | Все мутации скрыты, причина видна текстом |

Идемпотентность: `idempotencyKey = crypto.randomUUID()` создаём один раз на намерение отправить и держим в состоянии формы до успеха. Новый ключ — только после изменения payload. `expectedRevision` берём строго по контракту: `Cycle.revision` для cycle-мутаций, `Learning.revision` для start, `Session.revision` для submit. После каждой мутации делаем invalidate `Learning` и `study-plan`.

## 6. Критерии приёмки FE (для Codex и для ревью Opus)

1. Просмотр, сохранённая правка и засчитанная проверка выглядят по-разному на V1, V2, V5 и в итоге недели. Ни один экран не сводит их в одно число или один «прогресс».
2. Нигде нет числовых bands из learning API. Счётчик правила показан только при `checkPossible`. Для W/S и draft-материалов вместо числа стоит текст недоступности.
3. Нет запрещённых формулировок §1. Ревью проверяет это `rg` по пользовательским строкам новых файлов: `освоен|улучш|прогноз|до band|повыс|стрик`. Отдельно проверяется, что в текстах нет процентов освоения.
4. `assisted` не имеет значения по умолчанию. Отправка без явного выбора невозможна.
5. Ключ и model paragraph не появляются в V2/V3 до сохранения правки. FE не обходит legacy-политику.
6. Typed Speaking везде подписан как «не свидетельство речи». Аудио отправляется только через `audioAttemptId` из существующего потока.
7. `readOnly`/`readOnlyReason` скрывает мутации на всех новых экранах и в DRILL-строках плана.
8. 409/422/сеть не теряют введённый текст. Повтор идёт с тем же ключом.
9. 360px light и 728px dark: нет горизонтального overflow, tap-цели ≥44px, статусы различимы без цвета.
10. Визуальные запреты §4 соблюдены: никаких новых бейджей, плиток, полос, градиентов, иконок у строк.
11. Playwright покрывает сценарии: L/R правка `correct` → проверка `independent passed`; правка `incorrect`; W/S `unverified` без счётчика; draft-drill «практика»; день после экзамена read-only; 409 с сохранением ввода.

## 7. Честные ограничения, которые видит ученик

- Короткие тренировки сейчас — черновой материал. Их ключи дают практическую обратную связь, но не засчитываются в правило. `demonstrated` фактически недостижим, пока нет reviewed-заданий с размеченными семействами. Экран это показывает, а не прячет.
- Writing/Speaking: правки и тренировки сохраняются без проверки. Независимая проверка требует специалиста, и сейчас её нет.
- Typed Speaking ничего не говорит о беглости и произношении. Pronunciation в текущем пути не оценивается.
- Интервал «3 дня» и «две проверки» — правило продукта для практики. Это не норма IELTS и не прогноз результата.
- Ни один экран не обещает рост band за месяц или за N заданий.

Предложения к контракту на потом (FE не блокируют): persist-эндпоинт итога недели (`POST /study-plan/weeks/{week}/retrospective`); дата следующей проверки прямо в `Cycle` (`nextCheckDate`); локализованный `MicroSkill.title` на русском.

## 8. Открытые вопросы к основному агенту

1. Можно ли сохранить повторную правку после `verdict='incorrect'` (второй `POST /correction`) или это 409? От ответа зависит, показывать ли в V2 «Исправить ещё раз».
2. Как FE получить дату отложенной проверки? Сейчас её можно взять только из назначения плана с `drillId === cycle.nextDrillId`. Если такого назначения нет, показываем «Дата пока не назначена».
3. `MicroSkill.title` приходит на английском (`True/False/Not Given`) или на русском? Бриф предполагает термины IELTS на английском, как в UI сейчас.

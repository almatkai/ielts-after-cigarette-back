# AI-провайдеры и резервное переключение

Управление: **Админка → AI-провайдеры** (`/admin/ai-providers`). Только роль `ADMIN`; `EDITOR` и студенты не имеют доступа к API управления.

## Настройка перед запуском

1. Применить миграцию `000031_ai_providers` обычным способом.
2. Создать независимый случайный ключ: `openssl rand -base64 32`.
3. Сохранить его как `AI_PROVIDER_ENCRYPTION_KEY` в защищённом хранилище секретов окружения. Одинаковый ключ нужен API и worker. Не использовать JWT secret или API-ключ провайдера.
4. Настроить `SENTRY_DSN` на проект GlitchTip. Worker использует тот же DSN; `SENTRY_WORKER_DSN` позволяет выделить отдельный проект.
5. Перезапустить API и worker. Пока таблица провайдеров не создана, GET настроек возвращает `200` с `migrationRequired: true` (настроенный `.env` виден как read-only запись), а интерфейс показывает предупреждение и блокирует добавление. Ошибки соединения/прав не маскируются этим режимом. Операции над отсутствующей таблицей возвращают `503 AI_PROVIDER_MIGRATION_REQUIRED`. После миграции следующий GET автоматически снимает предупреждение. Без шифрования интерфейс не позволяет сохранять ключи; без error sink нельзя включать или тестировать провайдеры. Наличие encryption key без `SENTRY_DSN` — ошибка конфигурации при старте, кроме явно включённого локального режима ниже.
6. Добавить провайдера с полным **публичным HTTPS chat-completions URL** и ID модели, нажать «Проверить подключение», затем включить и сохранить.

Настроенный `AI_*`/`OPENROUTER_*` провайдер виден в общем списке с меткой `.env`. По умолчанию его приоритет — 10000; админ может задать название, приоритет, scopes, таймаут и включение, а также проверить подключение. Ключ остаётся только в окружении API/worker, URL и модели доступны только для чтения. В существующей таблице хранится служебная запись UUID `00000000-0000-0000-0000-000000000001` с настройками и зашифрованным маркером ссылки, **не копией API-ключа**. GET ничего не записывает; первая запись появляется только после сохранения админом. Новая миграция не требуется. Провайдер `.env` нельзя удалить из админки; после изменения его ключа/URL/модели в окружении нужен restart. При сбое БД используется исходная конфигурация `.env` как аварийный резерв. Не удалять её до настройки резервной цепочки. Реальная доставка ошибок зависит от доступности GlitchTip; тесты используют изолированный error sink, а не рабочий GlitchTip или платные AI API.

## Локальная разработка без GlitchTip

В локальном `.env`: `APP_ENV=development`, `AI_PROVIDER_TELEMETRY_OPTIONAL=true`, `SENTRY_DSN=`. Ключ `AI_PROVIDER_ENCRYPTION_KEY` всё равно нужен для шифрования; API и worker используют один и тот же ключ. В этом режиме добавление, включение и тестирование провайдеров доступны без GlitchTip, а санитизированные ошибки остаются в логах backend. GET возвращает `errorReportingRequired: false`, чтобы интерфейс не блокировал работу. По умолчанию opt-out выключен; в production/staging этот флаг запрещён и запуск завершается ошибкой конфигурации. Не переносить локальный флаг в окружение production.

## Уровни, ротация запросов и статистика

Основной редактор — **уровни с вертикальными стеками**. Одинаковый числовой `priority` объединяет провайдеров в один уровень. Новые операции распределяются round-robin: запрос 1 → A, запрос 2 → B, запрос 3 → C, запрос 4 → A. Одна операция никогда не отправляется всем участникам одновременно. Другие провайдеры получают её только при ошибке/таймауте, по одному; следующий приоритет используется после исчерпания текущего уровня. Разные пользовательские запросы могут одновременно обслуживаться разными провайдерами. Доступно на миграции 000031, без 000032. Приоритет можно изменить в форме, через выбор уровня в карточке или перетаскиванием в стек/«Новый уровень»; перенос сохраняет только переносимую запись с проверкой revision, не перенумеровывает остальные и не разбивает существующие стеки. Один уровень может включать и DB, и `.env` провайдер. Legacy side-effect `Run` остаётся последовательным; основные assistant/grading пути используют изолированный `Execute`.

Legacy атомарное API порядка `POST /api/v1/admin/ai-providers/order` принимает весь список `items: [{id,revision}]` и сохраняет порядок атомарно, включая виртуальную `.env` запись. Конкурирующие изменения дают `409`; частичный порядок не применяется. Для этого достаточно миграции 000031.

Миграция `000032_ai_routing_stats` создаёт конфигурацию, историю измерений и общие счётчики `ai_provider_rotation`. Атомарный PostgreSQL upsert выдаёт следующую позицию отдельно для уровня/purpose: все API и workers делят одну ротацию, счётчик сохраняется при перезапуске. До миграции или при сбое счётчика используется защищённая mutex локальная ротация процесса. Никаких prompts/answers в счётчиках нет. Scopes/enabled и глобальная speaking-audio политика сохраняются.

GET/PUT `/api/v1/admin/ai-providers/routing` оставлен для совместимости с revision locking; разрешён только `mode: sequential`, legacy `maxParallel`/`hedgeDelayMs`/`providerIds` не включают fan-out. Старые hedged-конфигурации также не могут превратить запрос в гонку. UI гонки удалён: распределение определяется уровнями. Общий бюджет операции — 180 секунд, каждый провайдер пробуется не более одного раза. Недоступность списка провайдеров сохраняет аварийный `.env` резерв.

GET `/api/v1/admin/ai-providers/stats?days=1|7|30` возвращает `models` (по provider/model/purpose) и 50 `recent` попыток. Измеряются полное время, время первого HTTP-ответа и первого streaming-токена, исход, победа, причина запуска, безопасный code/status и correlation IDs. Все попытки логируются в структурированный backend log; после миграции дополнительно сохраняются в БД. История имеет rolling retention 30 дней, очистка запускается при записи не чаще раза в час. Нет endpoint, API-ключей, промптов, student answers или raw upstream ошибок. Отмена пользователем не считается provider failure и не отправляются как ошибка в GlitchTip; реальные ошибки, даже при успешном резерве, по-прежнему отправляются в обычном режиме. Скорость p50/p95 считается по завершённым корректным ответам, отдельно по задаче; незавершённые и ошибочные операции в latency успешных ответов не входят. Успешность — валидность операции, **не качество IELTS оценки**. Для объективного качества нужен отдельный benchmark с эталонами; короткий probe не заменяет grading benchmark.

Без миграции 000032 GET настроек/статистики открываются с `migrationRequired: true`, а уровни продолжают работать с локальной ротацией. Только ADMIN имеет доступ к order/routing/stats. Локальный opt-out GlitchTip сохраняется.

## Поведение цепочки

- До 8 DB-провайдеров плюс один `.env`, единая сортировка по приоритету (при равенстве `.env` после DB, DB между собой по UUID); меньший приоритет вызывается раньше. Отключённые и не подходящие по scope пропускаются.
- Scopes: `assistant`, `writing`, `speaking`. Необязательный `speakingModel` заменяет основную модель только для Speaking.
- Одна цепочка используется Юки, синхронной оценкой и фоновыми Writing/Speaking workers. Настройки перечитываются на каждый новый запрос/задание; уже начатый запрос использует свой снимок.
- Таймаут провайдера — верхний предел (5–60 секунд). Общий бюджет цепочки — 180 секунд; он распределяется так, чтобы следующему провайдеру и `.env` оставалось время. Чтение конфигурации из БД ограничено 5 секундами; при сбое БД используется `.env`.
- Включая HTTP 429/5xx, таймауты, некорректный JSON/оценку, пустые ответы и обрывы SSE — операция повторяется на следующем провайдере. Это повтор **полной операции**, включая server-owned tool calls, а не только HTTP-запроса.
- Юки использует POST SSE. Перед резервным ответом `reset` удаляет незавершённый текст. Ответы разных моделей не склеиваются. EOF без корректного завершения — ошибка, а не готовый ответ.
- Если отказала вся цепочка, чат показывает нейтральное сообщение. Оценка работы не подменяется выдуманным баллом: существующие draft/retry и worker retry правила сохраняются.
- Отмена пользователем не запускает дополнительные платные запросы и не считается ошибкой провайдера.
- В обычном режиме все **ошибки провайдеров**, в том числе восстановленные fallback, отправляются через error sink в GlitchTip. В событии — ID, purpose, безопасный code/status и request ID; нет ключа, endpoint, тела ответа, prompt или работ студента.
- «Проверить» проверяет basic text completion выбранной модели без fallback. Это не полноценный IELTS grading или гарантированная поддержка каждой модальности. Из формы проверяются текущие несохранённые настройки; пустой API-ключ при редактировании использует сохранённый секрет.
- Глобальная политика `AI_SPEAKING_AUDIO_ENABLED`/speech pipeline сохраняется. Если отправляется raw audio, модели в Speaking-цепочке должны поддерживать OpenAI-compatible `input_audio`. Worker после STT оценивает расшифровку без повторной отправки аудио.

## Ключи и модель угроз

В PostgreSQL хранится только AES-256-GCM ciphertext с независимым случайным nonce. AAD связывает секрет с UUID записи и endpoint: подмена URL или перенос ciphertext в другую запись не позволяет отправить расшифрованный ключ злоумышленнику.

API возвращает `fromEnv` для отличия источника, но не возвращает ключ или ciphertext. В URL `.env` скрыты userinfo/query/fragment, чтобы не раскрыть встроенные credentials. Пустой `apiKey` при PUT сохраняет текущий секрет (и заново шифрует его текущим master key). Обновление/удаление защищено `revision` от перезаписи чужих изменений. Браузер не пишет ключи в local/session storage.

Админские endpoint требуют HTTPS, запрещают userinfo/query/fragment и нестандартные порты. Transport отключает proxy и redirects, проверяет **все** DNS-адреса на public IP и соединяется с проверенным IP, не выполняя второй DNS lookup. Loopback, private, link-local, CGNAT, reserved и известные IPv6 translation ranges запрещены. Доверенный `.env` URL сохраняет поддержку внутреннего endpoint.

Шифрование защищает при краже **только БД/её резервной копии**. Оно не защищает при одновременной компрометации API/worker/master key или от авторизованного администратора, который намеренно направит запрос на свой публичный endpoint. Secret store должен храниться отдельно от DB backups. Потеря master key делает сохранённые API-ключи невосстановимыми.

### Ротация

Для rolling deployment:

1. Распространить **старый current + новый previous** на все API/workers, чтобы каждый процесс умел читать ciphertext обоих ключей.
2. Затем поменять местами: **новый current + старый previous** на всех процессах.
3. В админке открыть и сохранить каждую запись, оставив `API-ключ` пустым: все записи будут перешифрованы новым current.
4. Только после обновления всех записей убрать previous и перезапустить процессы. Сохранить старый ключ отдельно в защищённом архиве, если ещё нужны DB backups, зашифрованные им.

## API

Все маршруты ниже требуют admin access token:

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/v1/admin/ai-providers` | `items`, `encryptionConfigured`, `errorReportingConfigured`, `envFallbackConfigured`, `maxProviders`, `migrationRequired`, `errorReportingRequired` |
| POST | `/api/v1/admin/ai-providers` | Создание; API-ключ обязателен |
| PUT | `/api/v1/admin/ai-providers/{id}` | Полная конфигурация и `revision`; пустой ключ сохраняет секрет |
| DELETE | `/api/v1/admin/ai-providers/{id}?revision=N` | Удаление с optimistic lock |
| POST | `/api/v1/admin/ai-providers/test` | Проверка конфигурации из body без сохранения |
| POST | `/api/v1/admin/ai-providers/{id}/test` | Проверка сохранённого провайдера; optional body переопределяет настройки |

Input: `name`, `endpoint`, `model`, `speakingModel`, `scopes`, `enabled`, `priority`, `timeoutSeconds`, `apiKey`, `revision`. List/save ответы содержат `hasKey`, но не `apiKey`/`key_ciphertext`. Test ответ: `ok`, `model`, `latencyMs`, при неудаче безопасный `code` и optional `httpStatus`. Ошибки: `422 VALIDATION_ERROR`, `409 REVISION_CONFLICT`, `503 AI_ENCRYPTION_UNAVAILABLE`, `503 AI_TELEMETRY_REQUIRED`.

### Юки SSE

`POST /api/v1/assistant/chat/stream` принимает прежний `ChatRequest`. Content-Type ответа `text/event-stream`, `Cache-Control: no-cache, no-transform`, `X-Accel-Buffering: no`. Authorization и автоматический refresh на 401 сохранены; действует rate limit.

Каждый frame — `data: <JSON>\n\n`:

- `{"type":"reset"}` — удалить только текущий незавершённый ответ;
- `{"type":"delta","text":"…"}` — добавить фрагмент;
- `{"type":"done","response":{"message":{"role":"assistant","content":"…"}}}` — полный канонический ответ, optional `toolCalls`;
- `{"type":"unavailable","text":"…"}` — нейтральное сообщение после исчерпания цепочки.

Старый `/api/v1/assistant/chat` сохранён для JSON-клиентов и тоже использует fallback. Reverse proxy должен поддерживать SSE и read timeout не меньше 195 секунд; upstream buffering выключается заголовком `X-Accel-Buffering`.

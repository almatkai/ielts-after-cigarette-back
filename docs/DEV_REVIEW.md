## Итог

Это рабочая основа MVP, но не готовый к студентам продукт. Есть осмысленное разделение
Go-кода на HTTP handlers, сервисы и PostgreSQL repositories, JWT/RBAC, валидация,
версионирование материалов и транзакции. При этом пользовательские сценарии содержат
блокирующие ошибки, которые текущие unit-тесты не обнаруживают.

## Приоритетные замечания

### P1. Вложенные страницы всех навыков не отображаются

`iac-web/src/routes/dashboard.reading.tsx:6`, `dashboard.listening.tsx:6`,
`dashboard.writing.tsx:6`, `dashboard.speaking.tsx:6`, `dashboard.full-mocks.tsx:6`
назначают компонентом библиотеку без `Outlet`. При этом `routeTree.gen.ts` действительно
вкладывает `$materialId`, `$testId`, `$mockId` в эти маршруты. Библиотечные компоненты
также не содержат `Outlet`. Поэтому смена URL не приводит к показу задания.

Нужно вынести библиотеки в index-маршруты, а родителям оставить `Outlet` либо явно изменить
структуру вложенности. Ручное редактирование сгенерированного `routeTree.gen.ts` это не исправляет.
Вывод подтверждён анализом текущего дерева и компонентов; браузерный end-to-end не проводился.

### P1. Сессии Full Mock смешиваются с самостоятельной практикой

`internal/attempts/repository.go:46` ищет любую последнюю активную попытку материала,
не исключая попытки Full Mock. `internal/fullmock/service.go:88` создаёт такие попытки
заранее для всех четырёх навыков. Ссылки в
`iac-web/src/pages/fullmock/full-mock-session-page.tsx:162` передают только materialId,
не attemptId/sessionId. Страница затем снова вызывает обычный Start.

При нескольких сессиях с общим материалом или запуске обычной практики может открыться
не та попытка; пользователь способен ответить в «закрытой» секции через обычную библиотеку.
Нужна явная привязка UI/API к attemptId и проверка допуска к секции на backend.

### P1. Таймер и порядок секций не защищены на сервере

`internal/fullmock/service.go:157` только вычисляет DeadlineAt; `Advance`, SaveAnswers,
Submit и загрузка записей не проверяют дедлайн и принадлежность попытки текущей секции.
UI скрывает кнопки, но API допускает работу вне этого порядка. Дедлайн также зависит
от текущей редактируемой durationMinutes теста, а не от снимка параметров начатой сессии.

Нужны серверные ограничения и неизменяемый снимок параметров сессии. Сейчас Full Mock —
объединение тренировок, а не строгий экзаменационный режим.

### P1. Черновик может измениться после оценивания при гонке запросов

`internal/attempts/service.go:105` проверяет статус до начала сохранения.
`internal/attempts/repository.go:126` затем делает upsert ответов без блокировки попытки
и без повторной проверки её статуса в транзакции. Если Submit успевает завершиться между
этими действиями, запоздавший autosave может заменить текст уже оценённого ответа,
оставив прежние балл и feedback. Нужна общая блокировка/проверка состояния для Save и Submit.

Дополнительно `iac-web/src/features/attempts/attempt-session.ts:100` очищает dirty-набор
до успешного сохранения, а onError только меняет индикатор. Неудавшиеся изменения не
возвращаются в очередь для повтора. Автосохранение также не сериализовано и не имеет revision.

### P2. Без AI нет сдачи Writing/Speaking

`internal/attempts/service.go:222` и `:290` возвращают ErrAIUnavailable вместо сохранения
работы в ожидающую проверки очередь. Ошибка провайдера также не даёт завершить попытку.
Ручной проверки/очереди в текущем dev нет. Full Mock вследствие этого также нельзя закончить.
Нужен отдельный статус сдачи и независимая от него асинхронная/ручная проверка.

### P2. Публикация Full Mock не валидирует материалы; запуск не атомарен

`internal/fullmock/repository.go:112` меняет статус без проверки существования,
публикации и совместимости четырёх материалов. В миграции 18 ссылки на материалы — UUID
без внешних ключей. Можно опубликовать вариант, который нельзя начать.

`internal/fullmock/service.go:88` сохраняет попытки до `CreateSession`. Если одна из следующих
секций недоступна либо параллельный Start занимает уникальную активную сессию, уже созданные
попытки остаются в БД. Нужны валидация публикации и единая транзакция запуска.

### P2. Общая БД пока не даёт общего доступа к медиа

Listening и Speaking читают/пишут локальные файлы (`internal/listening/service.go`,
`internal/attempts/recordings.go`). S3/MinIO из альтернативной реализации здесь нет.
У каждого разработчика с отдельным backend будут собственные файлы, но общие ссылки в БД:
чужие аудио будут недоступны. До совместного наполнения нужен единый backend с хранилищем
либо интеграция общего S3/MinIO.

## Другие ограничения

- Импорт Speaking отсутствует и в маршрутах API, и в админке.
- `iac-web/src/lib/api/client.ts` обновляет JWT для JSON-запросов, но не для `blob`:
  загрузка медиа после истечения access token может возвращать 401.
- История на странице Progress запрашивает только Reading/Listening; полноценное отображение
  попыток Writing/Speaking туда ещё не добавлено.
- Для `internal/writing`, `internal/speaking`, `internal/fullmock` нет собственных тестовых файлов.
  Тесты AI-клиента и attempts есть, но не заменяют интеграционный тест полного сценария.
- Возможности и фактическая доступность моделей OpenRouter не проверялись живыми запросами.
  Оценки AI не проверялись на точность/калибровку и не должны выдаваться за официальный результат.
